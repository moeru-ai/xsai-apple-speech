# Electron example

This application verifies the complete package path: Vue renderer, limited preload bridge, Eventa Electron transport, main-process plugin, native Provider, and Apple Speech.

It uses the same 40/60 settings and playground structure as the AIRI hearing settings page:

- Speech settings select the transcriber and language. They also prepare assets and configure the public Apple Speech options.
- The playground switches between streaming and file input. Both paths use the same selected transcriber, language, options, and analysis context.
- Streaming captures the microphone through an `AudioWorklet`. It shows the current text, completed segments, and a 15-second latency trace.
- File input sends a selected audio file through xsAI. The request supports cancellation.

Automatic transcriber mode shows settings for SpeechTranscriber and DictationTranscriber. Apple applies each supported override after it selects the transcriber.

Advanced settings accept contextual phrases and DictationTranscriber custom language model paths. Enter one contextual word or phrase per line.

The compact renderer uses `@proj-airi/ui`, the Chromatic UnoCSS preset, UnoCSS Wind4, and Anime.js. It follows the light and dark visual language of the AIRI stage UI without copying its application routing or state architecture. Anime.js drives the page, completed transcript-row, and appended-grapheme transitions.

Run the example on macOS 26:

```sh
pnpm build
pnpm --filter @xsai-apple-speech/example-electron dev
```

The `dev` script builds the native addon. It then stages the addon for the host architecture before Electron starts.

Build the unpacked application with:

```sh
CSC_IDENTITY_AUTO_DISCOVERY=false pnpm --filter @xsai-apple-speech/example-electron package
```

The Fakemic projects use a speech fixture generated by the macOS `say` command. They run the same live cases against development and packaged builds:

```sh
pnpm --filter @xsai-apple-speech/example-electron test:fakemic
```

These tests install Apple Speech locale assets and use real `SpeechAnalyzer` sessions. Treat them as integration tests on fresh hosted runners.
